# LKFJ 课程讨论稿 0.4｜全课程目录与 PPT 资料包蓝图

> **本版定位**：这是 LKFJ 全课程的总目录与 PPT 资料包索引。它以 G / A / P 的模块为最小设计单位，为后续将模块组合为 40 分钟 L 课时提供上游依据；不把“模块”与“一节课”简单等同。学生能力总纲以[《AI时代教育框架》](../../01_方法论/02_教育理念/01_AI时代学生能力框架.md)为准。

## Context

现有 0.1—0.3 已完成路径、模块与部分课时设计，G 与 A1 已有 HTML 页面。现在需要将 G、A、P 的全部课程统一放进一个可排课、可扩展、可追溯的目录中，并明确 PPT 页面制作的完成状态。

## Goal

1. 为 G0—G5、A1—A3、P1—P3 建立统一课程目录；
2. 为每个模块明确核心内容、建议课堂时间、最低交付和 PPT 页面状态；
3. 设计各层级的课程包，使其可按学生目的组合为 L 课时；
4. 将历史讨论稿与当前 PPT 资料包集中管理。

## Plan

1. 先通过专业探索 × AI 能力定位确认学生目的与起点；
2. 按本目录选择课程包与模块，再组合成具体 L；
3. 每个模块页面最终采用统一 PPT 结构：情境、目标、关键解释、案例、活动、回收；
4. 以真实任务、过程证据与学生判断作为完成依据。

## Out of Scope

- 本版不规定固定班型、售价、工具平台或教师排班；
- 不承诺自营全部 A3、P2、P3 的深度教学；这些层级也可用于转介、导师制或外部资源路线图；
- 本版不替代[《AI时代教育框架》](../../01_方法论/02_教育理念/01_AI时代学生能力框架.md)对人本根基、六块腹肌、持续学习与个性化发展的总体定义。

## Acceptance

- 每个模块有建议课堂时间与最低交付；
- 全部 69 个模块均可由本目录进入课件页：G0—G5、A1 为独立页面，A2、A3、P1—P3 使用统一的动态模块页；

## 1. 总体使用逻辑

### 1.0 与学生能力总纲的对应关系

G/A/P 是课程实施结构，不是另一套顶层能力分类。所有模块均须遵守“人类基线 → AI 协作 → 比较、核验并负责”的使用结构；课程应按学生需要补给能力，而不是让学生平均完成全部模块。

| 能力总纲 | LKFJ 中的主要承载方式 |
|---|---|
| 人本根基 | G0 的伦理、隐私、版权与责任；项目中的真实关系、风险边界与照护。 |
| 专注、理解、判断、表达、主见、创造 | G1/G2/G3/G4/G5 与项目全过程共同训练；不把它们拆成六门孤立课程。 |
| 持续学习 | 学习复盘、版本记录、反馈、纠错与再练习，贯穿 G/A/P。 |
| 个性化发展 | P 路径支持科学探究与求真，A 路径支持工程思维与系统实现；项目也可进入审美与文化感受、人文关怀与社会行动。 |

### 1.1 从 purpose 出发

| 先问什么 | 对应决策 |
|---|---|
| 我想解决什么学习、项目或专业问题？ | 选择 G、A、P 的入口与模块范围 |
| 我当前能独立完成什么？ | 判断是否需要先补 G 或低阶 A/P |
| 我希望最终成为工具使用者、产品实践者，还是算法/模型方向学习者？ | 选择 A 路径、P 路径或二者组合 |
| 我需要留下什么真实证据？ | 决定课程交付、作品集与评价方式 |

### 1.2 三层课程结构

| 层级 | 回答的问题 | 典型产出 |
|---|---|---|
| **G 通用层** | 如何负责任地学习、组织、表达、发现问题并与 AI 协作？ | AI 协作档案、学习系统、项目问题卡、作品集证据 |
| **A 应用层** | 如何把想法做成 Demo、轻量产品或可靠的软件系统？ | Demo、轻量产品、可维护软件与工程档案 |
| **P 原理层** | 为专业/学术问题，应学习到哪一层模型、算法与系统原理？ | 可复现实验、研究报告、基线复现或专题路线图 |

### 1.3 课程包总览

| 课程包 | 建议时间 | 适合对象与目的 | 结业交付 |
|---|---:|---|---|
| G0 责任底线包 | 180—200 分钟 / 约 5 L | 所有正式学习者 | AI 使用、数据、转介与核验原则 |
| G1 AI 通识与方法包 | 200—260 分钟 / 约 5—7 L | 希望正确开始使用 AI 的学生 | 带来源和人工检查点的协作任务 |
| G2 AI 学习增益包 | 300—380 分钟 / 约 8—10 L | 需要在学科学习中正确使用 AI 的学生 | 一套包含深度阅读、独立理解与复盘的 AI 学习档案 |
| G3 项目组织包 | 270—340 分钟 / 约 7—9 L | 已有资料、团队或项目任务的学生 | 可追溯的资料、任务、协作与决策系统 |
| G4 真实表达与作品集包 | 150—220 分钟 / 约 4—6 L | 需要展示方向与过程证据的学生 | 一页作品集与发布边界 |
| G5 问题与项目包 | 200—300 分钟 / 约 5—8 L | 从兴趣走向真实项目的学生 | 问题定义、计划、迭代与答辩 |
| A1 创客 Demo 包 | 220—320 分钟 / 约 6—8 L | 希望综合应用 AI 工具呈现想法的学生 | 有测试证据的 Demo 与过程档案 |
| A2 轻量产品包 | 720—960 分钟 / 约 24 L | 希望服务自己或小范围真实用户的学生 | 小范围可用产品、仓库、试用证据与维护计划 |
| A3 软件工程路径包 | 960—1200 分钟 / 约 24 L | 面向程序员/长期维护方向的学生 | 可解释、可测试、可部署的系统模块与维护记录 |
| P1 学术与专业赋能包 | 600—750 分钟 / 约 15 L | 用 AI/数据服务本专业问题的学生 | 可审查的小型研究或专业分析报告 |
| P2 AI/算法专业基础包 | 960—1200 分钟 / 约 24 L | 考虑 AI/算法专业学习的学生 | 可复现的代码、模型实验与实验卡 |
| P3 深度发展与路线图包 | 1200—1500 分钟 / 约 20 L | 面向算法/模型深度发展者 | 基线复现、风险评估或专题发展路线图 |

> **现有产品位置**：AI 创客营 = G0（贯穿）+ G1 + G4-1 + G5 + A1（按风险补 G0-4）；AI 大学预备营 = G0 + G1-2—G1-4 + G2-3—G2-4；一对一 = 先形成兴趣证据与项目建议卡，再按定位组合 G/A/P 模块。

### 1.4 两类实施路径

模块目录不等同于排课顺序。当前课程按两条路径实施，具体阶段、交付、停止条件与升级判断见[《AI营与一对一实施设计》](../../02_课程/02_课程框架/AI营与一对一实施设计.md)。

| 实施方式 | 课程逻辑 | 典型组合 |
|---|---|---|
| **AI 营** | AI 认知与边界 → 工具地图 → 兴趣／观察 → 问题定义 → 最小机制 → 制作、测试与展示。 | G0（贯穿）+ G1 + G4-1 + G5 + A1；按风险补 G0-4。 |
| **一对一** | 先形成兴趣证据与项目建议卡，再按项目类型、风险、责任层级和能力缺口组合模块。 | G0 为共同底线；G/A/P 不平均完成，按需进入 A1、A2、A3、P1、P2 或 P3。 |
