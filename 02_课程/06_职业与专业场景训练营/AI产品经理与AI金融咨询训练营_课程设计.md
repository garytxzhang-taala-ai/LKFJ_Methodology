# AI 产品经理工作坊与 AI 金融咨询训练营｜课程设计（v1）

> **课程库位置**：这是 LKFJ [《职业专项课程库》](00_职业专项课程库.md)的首发两条课程。职业方向用于组织真实任务与专项技能，不替学生确定职业，也不构成就业、实习或行业资格承诺。

## 一、先定课程承诺：不是工具速成，而是两种职业任务的完整练习

两门课共享的底层方法是：

```text
人类基线 → AI 协作 → 比较、核验并负责 → 形成可讲述的过程证据
```

它们不是把学生在一天内“培养成产品经理／咨询顾问／投行分析师”，而是让学生完成一次接近真实工作的、有边界的模拟项目，并留下可复盘的作品证据。

| 课程 | 职业任务主线 | 当天完成的最小闭环 | 课程位置 |
| --- | --- | --- | --- |
| AI 产品经理工作坊 | 从一个真实用户问题到可被体验的解决方案 | 调研假设 → 方案判断 → PRD → 最小 Demo → 测试 → Demo + PPT 汇报 | `G0 + G1 + G3/G4/G5 + A1` |
| AI 咨询投行训练营 | 模拟完成一份投资建议书 | 公司了解 → 行业研究 → 预测与估值 → 管理层访谈验证 → 建议与风险 → 报告 + PPT 汇报 | `G0 + G1 + G2/G3/G5 + P1` |

其中，产品营的最终交付为一个验证问题与核心体验的 Demo（A1）及其 PPT 汇报，不承诺可长期服务真实用户；金融营以公开、教学化资料和虚拟项目为对象，完成教学用途的投资建议书与 PPT 汇报，**不提供投资建议、个股推荐、募资建议或真实交易结论**。

### 旧复旦营如何作为参考，而非模板复刻

两份复旦营材料提供了很好的活动骨架：

| 旧营中值得保留的体验 | 新课程中的对应升级 |
| --- | --- |
| 先由行业从业者讲清岗位日常和真实挑战 | 开场使用“真实岗位任务卡 + 失败案例”，让职业认识成为当天项目的约束，而非单独职业宣讲 |
| 将咨询投行拆成定义问题、信息收集、建模分析、输出沟通 | 保留该流程，但加入来源核验、数据口径、反例和结论边界，形成可审查的研究闭环 |
| 将产品从需求转译、原型生成到逻辑验证串起来 | 扩展为用户证据、方案选择、Mini PRD、核心 Demo、可用性测试与迭代，避免只做“提示词生成页面” |
| 让人文社科学生看见自身优势 | 不把学科背景当口号：把深读、结构理解、叙事、同理、伦理与沟通转成具体可评分动作 |
| 现场实战和作品呈现 | 保留；评分由“完成度/页面好看”改为问题、证据、判断、测试、表达与复盘 |

新版本不以某个模型、编辑器或工具品牌作为课程卖点，也不使用“入场券”“一天获得硬核竞争力”这类承诺。工具会变化，学生更需要带走的是能够迁移到下一种工具的工作流和判断标准。

## 二、共同的“核心素养”，要嵌入任务，而不是单独讲完

| 共同素养 | 在产品营的可见动作 | 在金融咨询营的可见动作 |
| --- | --- | --- |
| 专注 | 先完成观察与问题卡，再打开生成工具；保留版本记录 | 先读任务材料、写研究假设，再检索与处理数据 |
| 理解 | 复述用户情境、区分需求/方案/功能 | 区分客户问题、事实、假设、观点与结论边界 |
| 判断 | 核验访谈/资料，建立方案选择标准，拒绝不合理功能 | 分级来源、核对原始数据、检查图表与结论是否匹配 |
| 表达 | 用用户故事、PRD、Demo 和路演讲清“为什么这样做” | 用报告结构和 PPT 讲清“发现什么、意味着什么、建议什么” |
| 主见 | 选择值得解决的问题，明确非目标和人机分工 | 选择分析口径，写出不确定性及“不应下的结论” |
| 创造 | 将洞察变成可测试的核心流程并据反馈修改 | 将散乱信息组织为有决策价值的观点、图表与故事线 |

每组都需提交一页“AI 协作与责任记录”：人先做了什么、AI 参与了什么、核验了什么、采用/否决了什么、局限是什么。它比提示词截图更能成为作品证据。

## 三、课程一：AI 产品经理工作坊｜从洞察到可测试的 AI 产品 Demo

### 1. 对外定位

适合想了解产品、创业、运营、设计或 AI 应用的大学生。学生不必会代码；重点不在生成一个漂亮页面，而在于能否围绕真实对象完成一次“发现问题—做出选择—验证核心流程”的产品过程。

**建议名称：** `AI 产品经理工作坊｜从用户问题到第一个可测试的 AI 产品 Demo`

**最终交付：**

- 一个可体验的 A1 Demo 或高保真交互原型；
- 一份产品汇报 PPT（包含问题、证据、取舍、核心体验、测试与下一步）。

问题卡、调研证据、Mini PRD 与测试记录是过程材料，用来支撑最终的 Demo 与 PPT。

### 2. 一天流程（09:00–17:30）

| 时间 | 模块与任务 | 专项能力 | 素养主练 | 产出/验收 |
| --- | --- | --- | --- | --- |
| 09:00–09:25 | 开场：AI 是基础设施，不是产品功能堆砌；看一个“流畅但不可用”的 AI 产品案例 | AI 能力/局限、责任边界 | 理解、判断 | 写下一个 AI 不能替自己决定的产品判断 |
| 09:25–10:10 | 任务 1：人类基线的用户问题拆解。用岗位任务卡/校园场景卡，写“谁在何时何地，因何种障碍无法完成什么” | 用户、场景、JTBD/痛点、问题范围 | 理解、主见 | 问题卡；明确不做什么 |
| 10:10–10:25 | 休息 |  |  |  |
| 10:25–11:20 | 任务 2：用 AI 扩展调研，而非替代调研。比较替代方案，检索并核验关键资料；将“AI 猜测”与“已有证据”分开 | 桌面研究、竞品/替代方案、来源核验 | 判断、专注 | 3 条可追溯证据 + 1 条待验证假设 |
| 11:20–12:00 | 任务 3：方案发散与选择。AI 生成备选路径，学生先建评价矩阵（价值、可行性、风险、验证成本），再选择核心机制 | 头脑风暴、优先级、决策记录 | 判断、主见、创造 | 方案矩阵与选择理由 |
| 13:30–14:15 | 任务 4：把想法写成能执行的 Mini PRD。包括用户故事、核心流程、异常/拒绝回答、AI 分工、验收标准 | PRD、用户旅程、需求澄清 | 表达、理解 | 一页 Mini PRD；未通过验收不进入制作 |
| 14:15–15:30 | 任务 5：Demo 冲刺。选择最合适媒介：交互原型、网页、对话流程、表格/自动化或演示型页面；只做一个关键体验 | 原型设计、AI 辅助搭建、Demo 叙事 | 创造、专注 | 可体验核心流程（不是完整 App） |
| 15:30–15:45 | 休息 |  |  |  |
| 15:45–16:20 | 任务 6：可用性测试。另一组按任务卡试用，记录“卡在哪里、以为会发生什么、是否愿意继续” | 测试设计、观察、反馈 | 理解、判断、表达 | 至少 2 位测试者的反馈记录 |
| 16:20–16:50 | 任务 7：只改一件最重要的事；补齐 AI 披露与风险边界 | 迭代、产品取舍、风险说明 | 主见、创造 | V1/V2 对照和修改理由 |
| 16:50–17:30 | 产品路演与复盘：问题—证据—决策—核心体验—测试—局限—下一步 | 路演、答辩、PPT | 表达、判断 | 3 分钟路演 + 个人离场卡 |

### 3. 产品项目题目应有边界

推荐使用“校园/学生生活中的低风险效率与学习问题”，或由主办方准备同样低风险的案例包。例如：跨校活动信息筛选、课程资料检索与复习规划、社团新人交接、实验室资料导航。不得制作医疗、心理诊断、法律建议、投资建议等高风险助手，也不收集真实敏感个人信息。

### 4. 产品营的核心评价（100 分）

| 维度 | 分值 | 看什么 |
| --- | ---: | --- |
| 问题与对象 | 20 | 是否具体、有场景，且没有把“做一个 App”当问题 |
| 证据与判断 | 20 | 是否区分事实/假设，资料是否可追溯，方案选择是否有标准 |
| PRD 与人机分工 | 20 | 流程、边界、验收标准是否清楚；人是否保留关键决定权 |
| Demo 与测试 | 25 | 是否只验证一个机制，是否完成实际测试并据此修改 |
| 表达与复盘 | 15 | 是否能说明局限、AI 参与和下一步验证 |

## 四、课程二：AI 咨询投行训练营｜从商业价值判断到投资建议书

### 1. 对外定位

适合想探索咨询、投行、行研、战略或商业分析的大学生。课程以公开资料充分的虚拟投资项目为案例，学习商业（价值）思维：一项业务为何值得投、靠什么创造价值、在什么条件下能够带来回报，又会被哪些风险推翻。

**建议名称：** `AI 咨询投行训练营｜用商业价值思维，完成一份投资建议书`

一天营不替代专业投行训练，更不构成真实投资建议。它练的是这些职业共同的底层工作：把问题讲清、用证据拆解商业价值、用模型说明假设、识别风险，并把判断讲给决策者听。

**最终交付：**

- 一份教学用途的投资建议书；
- 一份投资建议汇报 PPT，并完成模拟投资委员会汇报。

课程工作台会保存行业研究、投资回报、投资建议与风险分析四项任务中的 Prompt、AI 草稿、学生修改稿与最终确认稿；估值数据、管理层访谈和报告图表联动。它们构成可复盘的过程证据，支撑两项最终交付。

### 2. 一天流程（09:00–17:30）

| 时间 | 模块与任务 | 专项能力 | 素养主练 | 产出/验收 |
| --- | --- | --- | --- | --- |
| 09:00–09:25 | 开场：AI 能加速研究，但不能替代来源、分析口径与结论责任；识别一页“看似专业、实则失实”的报告 | AI 边界、研究诚信、披露 | 判断、理解 | 标出 3 个不可直接采用的地方 |
| 09:25–10:05 | 任务 1：了解公司与投资 Brief。阅读公司材料，将模糊要求改成投资对象、决策问题、价值来源、时间范围及“本次不回答什么” | 商业问题定义、价值链、假设树 | 理解、表达、主见 | 投资问题卡 + 初步价值假设 |
| 10:05–10:20 | 休息 |  |  |  |
| 10:20–11:20 | 任务 2：行业与商业价值研究。用公开资料验证市场空间、竞争格局、客户需求、商业模式与增长驱动 | 行业研究、商业模式、来源核验 | 判断、专注 | 关键事实表 + 价值驱动图 |
| 11:20–12:00 | 任务 3：财务与回报分析。读懂收入、成本、利润、现金流和单位经济；设定乐观/基准/压力三种回报情景 | 财务分析、单位经济、情景分析 | 判断、表达 | 财务摘要 + 回报假设表 |
| 13:30–14:15 | 任务 4：估值建模。下载预测 CSV，在教学模型中填写/上传假设；形成财务预测、DCF/可比公司估值和关键图表 | 估值逻辑、模型假设、敏感性分析 | 理解、判断 | 可复核的预测表、估值结果与图表 |
| 14:15–14:45 | 任务 5：管理层访谈。围绕收入、毛利率、费用、资本开支、税率和 WACC 提问，以访谈信息校准预测假设 | 访谈提问、信息提取、建模验证 | 理解、判断 | 访谈记录 + 已更新的模型假设 |
| 14:45–15:15 | 任务 6：投资建议与风险分析。写出投/不投建议，检查市场、竞争、技术、执行、财务、合规与退出风险 | 风险框架、反例、尽调思维 | 判断、主见 | 建议要点 + 风险矩阵 + 待验证事项 |
| 15:15–15:30 | 休息 |  |  |  |
| 15:30–16:20 | 任务 7：完成投资建议书与 PPT。确认稿自动汇入专业报告格式，展示公司介绍、行业、财务预测、估值、建议和风险；可导出 PDF | 投资备忘录、金字塔结构、PPT | 表达、创造 | 投资建议书 + 6 页以内 PPT |
| 16:20–17:05 | 任务 8：模拟投资委员会。一组汇报、另一组扮投资委员，专门追问“为什么投/不投、依据是什么、风险如何处理” | 口头汇报、Q&A、抗辩 | 表达、判断 | 汇报记录；修改一条关键判断 |
| 17:05–17:30 | 复盘：阅读 AI 使用报告，检查 Prompt、AI 草稿、修改稿和确认稿；识别是否核验来源、批判性采用 AI 内容 | 反思、AI 协作与责任 | 主见、专注 | AI 使用复盘 + 个人离场卡 |

### 3. 案例包设计：统一材料，避免“搜索能力”变成资源差异

每期设置一个低风险、公开信息充分的行业案例，如“某校园消费赛道的进入机会”“某公共服务行业的数字化趋势”或“一个虚拟企业的市场进入选择”。主办方给每组相同的 Brief、公开资料起点、教学数据和引用规范；学生仍要完成检索、筛选、核验和判断。这样才能评价研究能力，而不是谁更早知道某个行业或获得付费数据库。

除行业、财务、估值与风险外，可补充练习管理团队、增长策略、交易条款与退出路径的基础判断。严禁使用非公开交易材料、真实客户机密、个人账户数据或未经授权的公司内部资料。

### 4. 核心评价（100 分）

| 维度 | 分值 | 看什么 |
| --- | ---: | --- |
| 商业价值判断 | 20 | 是否讲清价值来源、客户需求与竞争位置 |
| 行业与证据研究 | 20 | 关键事实是否可追溯，是否区分事实、假设与观点 |
| 财务、回报与估值 | 25 | 模型口径和假设是否可解释，是否呈现情景与局限 |
| 风险识别与建议边界 | 15 | 是否识别关键风险，并提出验证或缓释动作 |
| AI 协作与过程核验 | 10 | 是否比较 AI 草稿与最终采用稿，核验关键来源与数据 |
| 投资建议书与 PPT 汇报 | 10 | 结论是否清晰，证据能否支持判断，能否回应追问 |

## 五、共用的教学物料与运营设置

- **建议规模：**24–36 人，3–4 人一组；每 6 组至少 1 名助教/导师。
- **课前 20 分钟：**工具与账号检查；填写职业兴趣、熟悉工具、想研究的问题；不要求编程基础。
- **避免工具绑架：**准备三种交付模板（幻灯片、文档/表格、交互原型）；网络或账号失效时，纸质案例包和离线截图仍可完成核心任务。
- **固定项目证据包：**问题卡、来源/数据表、AI 协作记录、V1、测试/质询记录、V2、局限和 30 天行动卡。
- **结营后的第二现场：**建议 30 天内一次线上作品复盘：学生补一条真实访谈/测试或一条高质量来源，并更新作品页。否则一天的成果很容易退化为“当天做出来的漂亮文件”。

## 六、Plan A 与 Plan B：评价与建议

| 维度 | Plan A：两个独立一日营 | Plan B：共享基础日 + 专业日 |
| --- | --- | --- |
| 招生叙事 | 最清楚：学生直接按职业兴趣选择 | 第一日容易显得泛，需要学生承诺第二日才感到职业价值 |
| 一天内成果 | 每个学生都能完成一个职业相关闭环 | 第一日只能有共同练习；真正的作品要等第二日 |
| 教学完整性 | 基础素养在专业任务中反复练，迁移更自然 | 共同基础可讲得更扎实，第二天也有更完整的专业项目时间 |
| 运营效率 | 两套案例/讲师/物料，成本较高 | 共同日可复用，师资与材料效率高；但第二天需按方向分班 |
| 班级体验 | 同伴目标一致，讨论和反馈更聚焦 | 若同班学生方向差异大，共同日的职业代入感会下降 |
| 适合的商业阶段 | 首期开营、需求仍需验证、学生只能投入一天 | 已有稳定招生、同一批学生愿意连续两天、能保证专业分班规模 |

### 结论：先以 Plan A 上市，把 Plan B 作为可叠加的进阶产品

建议当前主推 **Plan A**：两个名称、两条职业承诺、两套一日闭环。理由不是“基础素养不重要”，恰恰相反——基础素养在产品的调研、PRD、测试里，或金融咨询的检索、数据、报告里更容易被学生看见和练习；若抽成一整天，第一天很容易重新变成工具课。

同时，将两门课的第一个 75–90 分钟做成可复用的共同模块（AI 原理与边界、G/A/P 路径、人类基线、任务说明与核验）。当出现以下条件时，再把它产品化为 Plan B：

1. 同一招生渠道中，有足够多学生愿意连续参加两天；
2. 第二天每条专业线至少能形成 12 人左右的有效小组学习；
3. 能承诺课后一次真实反馈/作品复盘，而不只多上一天工具；
4. 共同第一天的产出会被第二天直接调用（共同证据包、个人路线图、AI 协作规范），而不是重新做一次泛泛练习。

若采用 Plan B，建议课程结构为：

```text
Day 1（共同）：AI 素养与通用工作流
人类基线 → AI 协作 → 来源/数据核验 → 人机分工 → 清晰任务说明 → 小型共同案例

Day 2A（产品）：用户问题 → PRD → Demo → 测试 → 路演
Day 2B（咨询投行）：公司了解 → 行业/财务分析 → 估值 → 管理层访谈 → 投资建议书 → 投资委员会汇报
```

第一天不要以“学会一堆工具”为目标；最低有效产出应是：一张可复用的任务说明模板、一份来源核验表、一张人机分工图，以及一个个人职业方向的 30 天练习计划。

## 七、可直接用于宣传的两句定位

> **AI 产品经理工作坊：**不用把自己训练成“会做页面的人”。你会从一个真实用户问题出发，练习调研、判断、PRD、Demo 与测试，完成一份能讲清过程的产品作品。

> **AI 咨询投行训练营：**你会模拟一次完整的投资建议：从公司与行业研究、财务预测和估值，到管理层访谈校验假设，最后完成带风险说明的投资建议书与汇报。
